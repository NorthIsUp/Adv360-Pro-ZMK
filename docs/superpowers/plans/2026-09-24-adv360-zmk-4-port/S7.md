- [ ] **Step 2: Cherry-pick and squash per feature**

```bash
git switch -c adv360-z4.1-regroup adv360-z4.1   # adv360-z4.1 is still 9ebbeff0
title() {
    case $1 in
    C9) echo "Kinesis board config, build/test harness and fork CI" ;;
    C7) echo "input tuning: 15 ms debounce, extended report, larger queue" ;;
    C4) echo "backlight brightness scale, apply API, no ext-power settings" ;;
    C1) echo "Kinesis lighting core and lock-key indicators (C1, C2)" ;;
    C5) echo "&stp battery-indicator behavior" ;;
    C8) echo "mouse_key_press metadata and fallback to &trans" ;;
    C3) echo "split LED and backlight sync over the split transport" ;;
    C6) echo "split BLE fixes: none needed on main, typing-under-sync test" ;;
    esac
}
for c in C9 C7 C4 C1 C5 C8 C3 C6; do
    base=$(git rev-parse HEAD)
    for h in $(git log --reverse --no-merges --format=%H --grep "^adv360($c): " 9ebbeff0..adv360-z4.1-wip); do
        git cherry-pick "$h" >/dev/null || { echo "CONFLICT in $c at $h"; break 2; }
    done
    body=$(git log --reverse --format='%s%n%n%b' "$base"..HEAD | grep -v '^Co-Authored-By:')
    git reset -q --soft "$base"
    printf 'adv360(%s): %s\n\n%s\n\nCo-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>\n' "$c" "$(title $c)" "$body" |
        git commit -q -F -
done
```

Expected: eight commits, no `CONFLICT` line. A conflict means a shared file was edited out of the order above (for example a reviewer fix-up tagged with the wrong feature): `git cherry-pick --abort`, report the commit and file, and ask. The spec wants each commit to record its upstream overlap; the task bodies already do (C1: #3239, C8: #2950 and #3047), and the squash keeps every body.
