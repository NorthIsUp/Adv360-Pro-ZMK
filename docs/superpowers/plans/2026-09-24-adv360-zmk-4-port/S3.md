# S3 — C3 split LED + backlight sync on upstream's split transport Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The right half mirrors the left half's underglow (layer, effect, on/off), backlight (brightness, on/off) and lock indicators, including after sleep or a reconnect. The sync never delays or evicts key traffic.

**Architecture:** Two new central commands (K1) ride upstream's split transport. `split/central.c` broadcasts them and caches the last state, and it replays the cache whenever the active transport reports a status change. The BLE transport adds one extra "ready" status report per peripheral, sent once both new handles are found and the link is at L2 or higher. The BLE central gives the sync its own two `k_msgq`s. They use a `K_NO_WAIT` put, drop the oldest entry when full, and are drained by one `k_work` on upstream's existing `split_central_split_run_q` thread. There is no new thread or stack. On the peripheral, GATT chars 0x07/0x08 (K3) are appended last to the split service. Their write handlers go through the shared dispatcher `zmk_split_transport_peripheral_command_handler`, which calls the K2 apply APIs. The wired transport only needs the two payload sizes. A new BabbleSim test drives the real GATT path. It covers replay-at-ready, drop-oldest on a 15-deep burst, and non-blocking enqueue.

**Tech Stack:** C (Zephyr 4.1, ZMK), Kconfig, Zephyr BT host GATT, BabbleSim (`nrf52_bsim`, amd64 image), K6 harness.

## Review Focus

1. **Right half stale after sleep, wake or reconnect** (spec RF1). The peripheral comes back with handles zeroed and the link unencrypted. Expected: once the central finds both sync handles and the link is at L2 or higher, the last LED state, the last backlight state and the current HID indicators reach the peripheral, without waiting for the next change. State that was never set is never replayed as "off". Pinned by `tests/ble/split/kinesis-sync`: the state is set before the peripheral connects, and the snapshot requires `Kinesis LED: layer 3 effect 2 on 1`, `Kinesis backlight: brightness 60 on 1` and `Raising HID indicators changed event: 0` right after discovery (S3-T1).
2. **Lighting burst while typing** (spec RF2, A3). The underglow effect changes on every layer tap and the backlight steps repeatedly. Expected: the caller never blocks, a key event or `INVOKE_BEHAVIOR` is never evicted, and only stale sync entries are dropped. Pinned by `kinesis-sync`: 15 back-to-back LED updates against the 5-slot queue deliver exactly layers 20–24, then the backlight update. The central `k_panic()`s if any call returns non-zero or simulated time advances during the burst, which would mean a blocking put. The six upstream split tests pass unchanged (S3-T1).
3. **Writes before encryption** (R2 rule 2, zmk#2461). A write-without-response on an L1 link takes Zephyr's unsupported signed-write path. Expected: sync writes are skipped until L2, and the handle-0 and L1 cases are dropped, not sent. Pinned by the same test's timeline. At `connected` the drain logs `Peripheral 0 not ready for Kinesis sync` twice (LED and BL) and nothing reaches the peripheral before the ready replay (S3-T1).
4. **Double-scaled backlight on the right half** (S1 RF1). Expected: the wire carries the unscaled `state.brightness`, and each half applies its own `BRT_SCALE`. Pinned by S3-T2's code, which sends `state.brightness` rather than `zmk_backlight_get_brt()`, and by the K1 comment. S1-T2's `update-vals` suite pins the peripheral side.
5. **Sync compiled out on a real half.** A missed guard would silently leave the right half unsynced, because broken here looks like empty. Expected: the left ELF links both K1 helpers and the two sync queues, and the right ELF links both GATT write handlers plus `zmk_rgb_underglow_set_periph` and `zmk_backlight_update_vals`. Pinned by the ELF probe in S3-T1 step 4 and S3-T2 steps 1 and 4.

Not coverable in simulation, so it goes on the batched hardware checklist (spec, Testing 3). Power-cycle the right half, change layer and backlight on the left while it is off, then power it back on. It must show the new layer colour and backlight within about 1 s of reconnecting. Repeat after a sleep → wake.

## Scope notes and decisions (read from the code, verified in the prototype)

- **Pinned, implemented as given:** A3; K1 via `zmk_split_transport_central_command`; K3 UUIDs 0x07/0x08.
- **R2's five rules, as implemented.**
  1. The new types never enter upstream's `zmk_split_central_split_run_msgq`, so its `default: return;` cannot strand queued commands. `split_central_bt_send_command` routes them to the sync queues first.
  2. `kinesis_sync_write()` skips (returns from the per-entry helper, never from the drain loop) unless the slot is `CONNECTED`, both handles are non-zero, and `bt_conn_get_security() >= BT_SECURITY_L2`.
  3. The re-send is triggered from `split_central_security_changed` and from discovery. It goes via `notify_status_work` (a `k_work`), never from BT callback context.
  4. Own queues with `K_NO_WAIT` and drop-oldest, one per type, so an LED burst never evicts the latest backlight state.
  5. The peripheral cases `return`.
- **Replay design (R1 rule 3, refined).** `kinesis_sync_notify_if_ready(slot)` submits `notify_status_work` only when the slot becomes sync-ready, that is, when the second of these happens: both handles found, or security reaches L2. The check runs at the LED- and BL-handle discovery and at the top of `split_central_security_changed`, before upstream's physical-layout early return. `split/central.c`'s `transport_status_changed_cb` then calls `resend_peripheral_state()` for any non-disconnected status of the active transport. Earlier status reports (`connected`) also replay, and the drain drops those as not-ready. R1's variant fired on discovery and security independently. This variant fires once per ready edge, and that is what makes the indicator replay safe (next point).
- **Indicators are replayed too.** The Kinesis pin carried indicators inside its LED payload, so its reconnect restored caps-lock colours. K1 moved them to upstream's `SET_HID_INDICATORS`, which main never re-sends. `resend_peripheral_state()` broadcasts the current profile's indicators (`zmk_hid_indicators_get_current_profile()`) under `CONFIG_ZMK_SPLIT_PERIPHERAL_HID_INDICATORS`. They go through upstream's unchanged path. That path has no security check (R2 latent), so this is safe only because the ready trigger fires at L2 or higher. At the earlier `connected` report the indicators handle is still 0, so upstream drops the write (`NO HANDLE TO SET ON PERIPHERAL`).
- **Has-state (R1 rule 4).** The central caches are zero-initialised `struct zmk_split_transport_central_command`s. Their `.type` stays `POLL_EVENTS` (0) until the first update, and `resend_peripheral_state()` skips a cache whose type is 0. S2's init call (`zmk_rgb_underglow_init` → on/off → hook) and backlight init (`zmk_backlight_init` → `zmk_backlight_update`) set them at boot.
- **Queue, not coalesce.** K4 names the two queue sizes, and R1 open question 2 needs a K4 change before coalescing. So queues it is. Coalescing with a latest-state flag would remove both queues, which is a follow-up if the critic wants it.
- **One feature guard, not two.** `CONFIG_ZMK_SPLIT_KINESIS_SYNC` is `bool`, `default y if ZMK_RGB_UNDERGLOW || ZMK_BACKLIGHT`, and user-settable, so BSim can enable it on `nrf52_bsim`, which has neither. It guards the K1 prototypes, the chars, the handles, the queues and the dispatcher cases. The dispatcher calls `zmk_rgb_underglow_set_periph` / `zmk_backlight_update_vals` only when the feature exists, and otherwise just logs and returns 0. This is R1 open question 1, answered as "record it in K4" (contract addition).
- **Wire format (K3).** The central writes the K1 union members as-is (3 and 2 bytes, `BUILD_ASSERT`ed in `service.c`). The peripheral rejects `offset != 0` (`BT_ATT_ERR_INVALID_OFFSET`, R4) and any other length (`BT_ATT_ERR_INVALID_ATTRIBUTE_LEN`, K3). It normalises `on` with `!= 0`.
- **Indicators in K2's struct.** `zmk_rgb_underglow_set_periph` ignores `.indicators` (S2 contract addition), so S3 leaves it 0. Indicators reach the peripheral through `zmk_hid_indicators_changed` on both transports (R1 rule 1).
- **Wired.** Only the two `get_payload_data_size` cases. `wired/peripheral.c` already sends every type through the dispatcher. It is proven by a compile probe with a `zmk,wired-split` overlay on both halves. The adv360 has no wired DT node, and there is no wired test harness.
- **Upstream `ret` bug** (R1 rule 7). It is left alone (A3). `broadcast_command()` is a fresh loop that does not reuse `ret`.
- **Dropped Kinesis pieces:** the `*_STACK_SIZE` symbols and private threads, the central-side `zmk_split_peripheral_status_changed` raise, and the 2.5 s re-sync timer (R1, R2 rule 3, R4). S1 and S2 already left them out.

// Drives the Kinesis sync API on the central; the peripheral's log is the snapshot.

#include <zephyr/init.h>
#include <zephyr/kernel.h>

#include <zmk/split/central.h>

#if IS_ENABLED(CONFIG_ZMK_SPLIT_ROLE_CENTRAL)

// 15 LED updates against a 5-slot queue, back to back on the system work queue: only
// layers 20-24 may reach the peripheral. Simulated time only advances when a thread
// blocks, so any elapsed time means an enqueue blocked. A failure halts the central,
// which drops the burst lines from the peripheral snapshot.
static void kinesis_sync_burst(struct k_work *work) {
    int64_t start = k_uptime_get();

    for (uint8_t layer = 10; layer < 25; layer++) {
        if (zmk_split_central_update_kinesis_led(layer, 1, true) != 0) {
            k_panic();
        }
    }
    if (zmk_split_central_update_kinesis_backlight(40, false) != 0 || k_uptime_get() != start) {
        k_panic();
    }
}

static K_WORK_DELAYABLE_DEFINE(kinesis_sync_burst_work, kinesis_sync_burst);

// Set before the peripheral connects, so only the ready-time replay can deliver it.
static int kinesis_sync_test_init(void) {
    zmk_split_central_update_kinesis_led(3, 2, true);
    zmk_split_central_update_kinesis_backlight(60, true);
    k_work_schedule(&kinesis_sync_burst_work, K_SECONDS(3));
    return 0;
}

SYS_INIT(kinesis_sync_test_init, APPLICATION, 99);

#endif // IS_ENABLED(CONFIG_ZMK_SPLIT_ROLE_CENTRAL)
