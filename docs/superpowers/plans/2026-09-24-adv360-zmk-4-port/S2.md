# S2 — Lighting (C1 lighting core, C2 lock indicators, K5 rgb.h, K2 peripheral API) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Kinesis underglow runs on ZMK `main`: the Kinesis effect with 32 layer colours, BT-profile colours and lock-key indicators, the battery and test effects, `BRT_SCALE` brightness scaling, a momentary-effect key, no flash writes. The right half's apply API (K2) and one named central hook for C3 are ready for S3.

**Architecture:** The Kinesis hunks go into upstream's `app/src/rgb_underglow.c`, which is byte-identical to the merge-base (R4). Three deliberate changes from the pin:

- **Layer changes come from a `zmk_layer_state_changed` listener.** The pin polled the layer in the 50 ms tick. With the listener, the hook fires only when something changes (R1 §4).
- **Indicators come from upstream's `zmk_hid_indicators_changed` event on both halves** (K1). The central raises it from host reports and the peripheral from `SET_HID_INDICATORS`. The Kinesis wire byte is gone.
- **Every sync point calls one static function, `zmk_rgb_underglow_central_send()`.** Those points are layer change, effect change, on, off, and init via on/off. The function logs one line, which the tests pin. S3 adds the K1 send inside it.

The Kinesis central re-sync timer is dropped, because S3 replays state from the split layer (R1 TL;DR 2, R2 rule 3). A new native_sim suite drives a real `led_strip` device, a `ti,tlc59731` on the emulated GPIO controller. It covers all 32 layers × `BRT_SCALE` 0/1/50/100 against snapshots from an independent Python model, plus a suite for the effect keys.

## Review Focus

1. **Layer colours off by one, or brightness scaling wrong** (master plan RF4). Expected: every layer 0–31 renders the Kinesis colour pair at `BRT_SCALE` 0/1/50/100. Pinned by `app/tests/rgb-underglow/kinesis-layers/brt-{0,1,50,100}`, whose snapshots come from an independent Python model of the tables (S2-T1). A mutation control flips `<=` to `<` in `zmk_led_layer_to_colors` and must FAIL (S2-T1 step 4). In the prototype it failed at layers 8 and 15.
2. **Sync storm from the tick.** A hook that runs every 50 ms would flood the ATT queue that key events share (R1 §4). Expected: exactly one hook line per real change. Pinned by the snapshot: 65 lines for 62 layer changes, 2 on/off changes and 1 init line, with no line between key events (S2-T1). The `kinesis-effects` snapshot also shows no hook line for `RGB_COLOR_HSB` or for the rejected `RGB_EFS 7` (S2-T2).
3. **Momentary effect key that does not restore.** Expected: releasing `RGB_MEFS_CMD n` (and the `RFB_MEFS` alias) returns to the previous effect. Pinned by `kinesis-effects` (effect 6, then back to 1; effect 2, then back to 1) (S2-T2).
4. **Renumbered `RGB_COLOR_HSB_CMD` still reaching the handler.** K5 shifts it 14 → 15. A keymap or the convert path that used 14 would silently run `RGB_MEFS_CMD`. Expected: `RGB_COLOR_HSB(...)` arrives as command 15. Pinned by `RGB behaviour triggered (15/7877160)` in `kinesis-effects` (S2-T2).
5. **Garbage state from the wire on the right half.** `zmk_rgb_underglow_set_periph` gets S3's layer and effect from BLE. Expected: `-EINVAL` for layer ≥ 50 (the first layer the colour pairs cannot encode) or effect ≥ 7, and no out-of-bounds `LAYER_COLORS` read. Pinned by the guard in S2-T1's implementation. There is no native_sim coverage, because the split peripheral does not build for native_sim; S3's peripheral handler test owns the call path.

C2 has no automated test. `native_sim` cannot inject a host LED report, so C2 stays a hardware check (spec C2 row), and the board builds only prove the listener compiles on both halves.

## Scope notes (from reading the Kinesis diff, verified in the prototype)

- **Kept verbatim:** the colour tables, the formula in `zmk_led_layer_to_colors`, the Kinesis/battery/test effect bodies, the blink timings (2 / 13 ticks), `NUM_BT_COLORS 4` (profile 4 shows black, as on the pin), the settings removal, `zmk_rgb_underglow_save_state()` returning 0, the MEFS metadata (range max 6) and `BEHAVIOR_LOCALITY_CENTRAL`.
- **Fixed while porting (R4 defects):** `LED_RGB` uses integer math, `ch * BRT_SCALE / 250`. The pin's `(float)SCALE / 250.` triggered `-Wdouble-promotion` ×57. A check over every scale 0–100 × channel 0–255 found 0 differences against the pin's float result (`python3` probe, 2026-09-27). `ext_power` is used only through the existing guarded `on()`/`off()`. `last_ble_state`, `zmk_kinesis_blink_step` and `BT_COLORS` are compiled only when something uses them, so unsplit, BLE-less builds have zero warnings. The work handler signature question is gone because there is no Kinesis work item any more.
- **Dropped on purpose:**
  - `led_update_work` and the central `zmk_split_peripheral_status_changed` subscription (the 2.5 s re-sync). Main raises that event only on the peripheral (R4), and S3 replays from the split layer (R1, R2 rule 3).
  - The `AUTO_OFF_USB` branch's unguarded send and its unused `prev_state`. adv360 leaves `AUTO_OFF_USB` off, and on/off already hit the hook.
  - The dead `triggered` flag, which was written and never read.
  - The central's per-tick `zmk_hid_indicators_get_current_profile()` poll, replaced by the event.
- **Init:** `zmk_rgb_underglow_init()` ends with `return state.on ? zmk_rgb_underglow_on() : zmk_rgb_underglow_off();`. That keeps the Kinesis intent (ext power and strip forced to the start state) and fires the hook exactly once at boot. The central therefore always holds state it set itself, so R1 TL;DR 6's "zero replay" hazard does not arise once S3 wires the hook.
- **Owed by S0 (S0 scope notes):** `CONFIG_ZMK_RGB_UNDERGLOW_EFF_START=4` on both halves, and the board keymap's mod-layer key 39 `&none` → `&rgb_ug RGB_MEFS_CMD 5`. Both land in S2-T3.
- **`RGB_EFS` / `RFB_MEFS` macros** take their parameter from the keymap (`&rgb_ug RGB_EFS 1`), as on the pin. The user keymap uses neither, and neither does it use `RGB_COLOR_HSB` (R0).

- Produces:
  - K2, in `app/include/zmk/rgb_underglow.h`: `struct zmk_periph_led { uint8_t layer; zmk_hid_indicators_t indicators; uint8_t effect; bool on; };` and `int zmk_rgb_underglow_set_periph(struct zmk_periph_led periph);`. It applies layer, effect and on/off, and **ignores `periph.indicators`**, because indicators come from `zmk_hid_indicators_changed` (contract addition).   - The C3 hook, in `app/src/rgb_underglow.c`: `static void zmk_rgb_underglow_central_send(void)`, compiled under `#if KINESIS_LED_SOURCE`, where `KINESIS_LED_SOURCE` is `(!IS_ENABLED(CONFIG_ZMK_SPLIT) || IS_ENABLED(CONFIG_ZMK_SPLIT_ROLE_CENTRAL))`. It reads the file-static `led_data` (`.layer`, `.effect`, `.on`), which is already updated when it runs. It is called from:
    - `zmk_rgb_underglow_on()` and `zmk_rgb_underglow_off()`, so also toggle, idle auto-off and init;
    - `zmk_rgb_underglow_select_effect()` after validation, so also cycle, `RGB_EFS` and `RGB_MEFS_CMD` press/release;
    - the `zmk_layer_state_changed` listener, only when the highest layer changes.

    Today its body is only `LOG_DBG("layer %d left #%06x right #%06x effect %d on %d", …)`, and the tests pin that line. **S3 adds, after the `LOG_DBG` and without removing it:**

    ```c
    #if IS_ENABLED(CONFIG_ZMK_SPLIT_ROLE_CENTRAL)
        int err = zmk_split_central_update_kinesis_led(led_data.layer, led_data.effect, led_data.on);
        if (err) {
            LOG_ERR("Kinesis LED sync failed (err %d)", err);
        }
    #endif
    ```

    S3 also adds `#include <zmk/split/central.h>` under the same guard. The `ROLE_CENTRAL` guard keeps the unsplit native_sim suites building.
  - K4: `CONFIG_ZMK_RGB_UNDERGLOW_BRT_SCALE`, `CONFIG_ZMK_RGB_UNDERGLOW_MOD_COLOR`, and `EFF_START` range 0–5. The effect enum appends `UNDERGLOW_EFFECT_KINESIS` = 4, `_BATTERY` = 5 and `_TEST` = 6, so `UNDERGLOW_EFFECT_NUMBER` = 7.
  - Test pattern: the `ti,tlc59731` strip on `&gpio0 2` is a working `zmk,underglow` on `native_sim`, for any later suite.
