# R3 — Why Kinesis reverted layer names (#3047), and whether it matters on main

**Recommendation: KEEP-UPSTREAM.** Port nothing for #3047. Kinesis did not revert
it because of a layer-name, Clique or keymap-editor problem. Their cherry-pick
was missing a prerequisite commit, so every key on every build came out dead.
That can't happen on main, where the prerequisite is present. Porting the revert
onto main would bring back the bug #3047 fixed, and the user's keymap triggers
that bug: it has four `status = "reserved"` layers, and the no-clique build does
not enable Studio.

## 2. Root cause: #3047 depends on #2771, and the pin doesn't have #2771

Upstream #3047 ("Generate correct keymap layer names for all builds", fixes
#3045) builds on upstream **#2771** `e4f1454e` ("Reduce flash usage for studio
builds", merged 2025-01-15). #2771 added a third parameter, `no_init`, to
`KEYMAP_VAR`. It also added `reload_from_stock_keymap()` to `keymap_init()`, so
Studio builds leave the live keymap zeroed at compile time and copy it from the
stock keymap at boot.

```
$ git -C /Users/adam/src/zmk-adv360 merge-base --is-ancestor e4f1454e 3377ed02 || echo "2771 NOT in merge-base"
2771 NOT in merge-base
```

The pin's `KEYMAP_VAR` is still the two-parameter form, `KEYMAP_VAR(_name, _opts)`.
The cherry-pick inserted #3047's body line
`COND_CODE_0(no_init, (ZMK_KEYMAP_LAYERS_FOREACH_SEP(TRANSFORMED_LAYER, (, ))), (0))`
unchanged, so `no_init` became an undefined token. Zephyr's `COND_CODE_0` does not
reject an undefined token. It treats it as "not 0" and takes the else branch.
Probe against the real Zephyr v4.1.0+zmk-fixes headers:

```
$ printf '#include <zephyr/sys/util_macro.h>\nA: COND_CODE_0(no_init, (LAYERS), (0))\nB: COND_CODE_0(0, (LAYERS), (0))\nC: COND_CODE_0(1, (LAYERS), (0))\n' > nodef.c
$ cc -E -P -I /tmp/r3probe nodef.c | grep -E '^[ABC]:'
A: 0
B: LAYERS
C: 0
```

So on the pin with the cherry-pick applied, both `zmk_keymap` and
`zmk_stock_keymap` became `= { 0 }` on no-clique and clique builds alike. Every
binding had a NULL `behavior_dev`, so no key did anything. The build compiled
without warnings, which is why CI stayed green (PR #22 says the same). PR #22's
second hunk (`reload_from_stock_keymap()` in `keymap_init`) is the other half of
#2771, which the Studio build would also have needed.

## 3. Why the pin never needed #3047

Bug #3045: a `reserved` layer in a build without Studio fails to compile, with
thousands of lines of "excess elements in array initializer". #2771 introduced
it by making `ZMK_KEYMAP_LAYERS_LEN` count only `okay` children when Studio is
off, while the layer-names array still lists all children. The pin's
`ZMK_KEYMAP_LAYERS_LEN` never had that change and counts **all** children
(`DT_FOREACH_CHILD`), so the arrays always match. After the revert the pin
compiles and behaves correctly (table in §4, rows `pin-revert`). The cherry-pick
fixed a bug the pin didn't have and added one it didn't have before.

## 4. Empirical matrix: real macros × the user's real keymap

Probe `/tmp/r3probe/probe.py` (source below) reads the layer nodes from
`config/adv360.keymap`, generates a devicetree mock of their shape, and compiles
the **real** `ZMK_KEYMAP_LAYERS_*` / `LAYER_NAME` / `KEYMAP_VAR` / layer-name
blocks taken from each revision's `keymap.h` and `keymap.c`. The mocked parts are
the child iteration, the display-name read, and a one-entry `TRANSFORMED_LAYER`.
Zephyr's `util_macro.h` family comes from the v4.1.0+zmk-fixes tag. Layers parsed
from the real file: Base, Kp, Fn, Mod (`okay`); Red, Purple, Cyan, Yellow
(`reserved`). Configs: no-clique = nothing set; clique = `ZMK_STUDIO` +
`KEYMAP_SETTINGS_STORAGE` + `KEYMAP_LAYER_REORDERING`. On main, `ZMK_STUDIO_RPC`
selects the last two (`app/src/studio/Kconfig:45-46`).

```

pin-revert         clique    LAYERS_LEN=8 keymap=populated stock=populated -> COMPILES

main+revert        clique    LAYERS_LEN=8 keymap=ZEROED    stock=populated -> COMPILES
```

In the `main` clique row, `keymap=ZEROED` is correct: main's `keymap_init()`
calls `reload_from_stock_keymap()` under `CONFIG_ZMK_STUDIO` (main
`app/src/keymap.c:972-981`), and the stock keymap is populated. The
`pin-cherrypick` rows reproduce the dead-keys firmware from #848, where both
arrays are zeroed.

Same probe with the real container GCC (`zmkfirmware/zmk-build-arm:4.1`):

```
== gcc CFLAGS=''         main+revert no-clique -> COMPILES (with excess-initializer warnings)
== gcc CFLAGS='-Werror'  main+revert no-clique -> FAILS: excess elements in array initializer [-Werror]
```

ZMK does not set `-Werror` (`git grep -i 'WARNINGS_AS_ERRORS\|Werror' main -- app`
finds nothing). With GCC defaults, the reverted main build therefore emits the
#3045 warning flood and truncates the 8-entry name list to its first 4 entries.
For this user's keymap the names still come out right only because all four
`okay` layers come before the reserved ones. A keymap with a reserved layer
between `okay` layers would show the wrong layer names in no-clique builds. The
hard compile failure described in #3045 was not reproduced with plain flags; only
a full `west build` would show it (see §7).

### What `main+revert` means

`git revert 0b5a103c` on main (9ebbeff0) **does not apply cleanly**. It conflicts
in `app/include/zmk/keymap.h`, because upstream #3164 (`19582174`) later rekeyed
`ZMK_KEYMAP_LAYERS_FOREACH*` from `CONFIG_ZMK_STUDIO` to
`CONFIG_ZMK_KEYMAP_LAYER_REORDERING`. The probe resolves the conflict the way the
revert intends: it deletes the `FOREACH` macros, which nothing else on main uses
after the revert (`git grep ZMK_KEYMAP_LAYERS_FOREACH` shows only keymap.h). The
resulting diff is §6 REVERT.

## 5. Does anything else in the question still apply on main?

- **Clique-saved keymaps / settings layout.** Neither #3047 nor its revert
  changes settings keys or the stored layout. Both only change which DT children
  feed compile-time initializers. In clique builds, LEN is 8 on every revision
  (table above), so the Studio layer ids and the saved names/bindings behind
  them are the same on the pin and main. The no_init path (#2771) is upstream
  behaviour on main and comes with its matching `reload_from_stock_keymap()`.
- **Keymap editor (Kinesis web configurator).** It generates the `.keymap`
  source. The firmware macro changes don't touch the source format.
  `display-name` is the property upstream reads (`LAYER_NAME` →
  `DT_PROP_OR(node, display_name, DT_PROP_OR(node, label, ""))`, the same on the
  pin and main). Searches of KinesisCorporation/Adv360-Pro-ZMK for "layer name"
  and "reserved" found nothing about the editor in 2026. July 2026 has one issue,
  #848, and that one is the dead-keys build. refil/zmk has issues disabled.
- **The only user-visible difference between the pin and main:** in the
  **no-clique** build, the pin sizes the keymap at 8 layers (reserved layers
  exist but are empty) and main sizes it at 4 (reserved layers are compiled out).
  The user's keymap references only layers 1–3 (`&tog 1`, `&mo 2`, `&mo 3`;
  grep in §7), so nothing addresses layers 4–7 without Studio. In the clique
  build both have 8.

## 6. The two options

### KEEP-UPSTREAM (recommended)

Diff: **none**. Main already has #2771, #3047 and #3164 as a consistent set.

User-visible: both halves work in no-clique and clique builds. The user's
reserved layers Red/Purple/Cyan/Yellow are available to add in Clique/Studio,
and they are compiled out of no-clique builds. Layer display names come from
`display-name`. No compile warnings. Per spec A1 ("Kinesis behaviour wins"),
nothing here is a Kinesis feature: the revert only undid a broken cherry-pick,
so C1–C9 parity does not require it. The S4 commit message should say "R3:
#3047 overlap — pin revert undid a prerequisite-less cherry-pick; main is
self-consistent, nothing to port".

`probe.py`:

```python
#!/usr/bin/env python3
"""R3 probe: compile the real keymap-array macros of each revision against a
devicetree mock generated from the user's real adv360.keymap layer nodes.
usage: probe.py <zephyr-include-dir> <keymap> <name>=<keymap.h>:<keymap.c> ...
env: CC (default cc), PROBE_CFLAGS (default -Werror=excess-initializers)"""
import re, subprocess, sys, tempfile, os

inc, keymap, *variants = sys.argv[1:]
src = open(keymap).read()
body = src[src.index('compatible = "zmk,keymap"'):]
layers = []
for m in re.finditer(r'\n\s{4}(\w+)\s*\{(.*?)\n\s{4}\};', body, re.S):
    name, blk = m.group(1), m.group(2)
    dn = re.search(r'display-name\s*=\s*"([^"]*)"', blk)
    st = re.search(r'status\s*=\s*"([^"]*)"', blk)
    layers.append((name, dn.group(1) if dn else "", st.group(1) if st else "okay"))

def dt_mock():
    ids = [f"N_{n}" for n, _, _ in layers]
    ok = [f"N_{n}" for n, _, s in layers if s == "okay"]
    out = ["#define DT_INST(i, c) KM"]
    def each(name, lst):
        out.append(f"#define {name}(node, fn) " + " ".join(f"fn({i})" for i in lst))
        out.append(f"#define {name}_SEP(node, fn, sep) " + " __DEBRACKET sep ".join(f"fn({i})" for i in lst))
    each("DT_FOREACH_CHILD", ids)
    each("DT_FOREACH_CHILD_STATUS_OKAY", ok)
    out.append("#define DT_INST_FOREACH_CHILD_SEP(i, fn, sep) DT_FOREACH_CHILD_SEP(KM, fn, sep)")
    out.append("#define DT_INST_FOREACH_CHILD_STATUS_OKAY_SEP(i, fn, sep) DT_FOREACH_CHILD_STATUS_OKAY_SEP(KM, fn, sep)")
    for n, dn, _ in layers:
        out.append(f'#define N_{n}_NAME "{dn}"')
    out.append("#define DT_PROP_OR(node, prop, dflt) node##_NAME")
    out.append("#define TRANSFORMED_LAYER(node) {{.behavior_dev = #node}}")
    return "\n".join(out)

def extract(h, c):
    H = open(h).read(); C = open(c).read()
    key = "#define ZMK_KEYMAP_LAYERS_FOREACH("
    start = H.index(key) if key in H else H.index("#define ZMK_LAYER_CHILD_LEN_PLUS_ONE")
    keep, in_len = [], False
    for line in H[start:].split("\n"):
        keep.append(line)
        if line.startswith("#define ZMK_KEYMAP_LAYERS_LEN") or in_len:
            in_len = True
            if not line.rstrip().endswith("\\"):
                break
    ln = re.search(r"#define LAYER_NAME\(node\).*", C).group(0)
    cs = C.index("#define KEYMAP_VAR")
    ce = C.index("#endif", C.index("static const char *zmk_keymap_layer_names", cs)) + 6
    return "\n".join(keep) + "\n" + ln + "\n" + C[cs:ce]

CONFIGS = {"no-clique": [],
           "clique": ["CONFIG_ZMK_STUDIO", "CONFIG_ZMK_KEYMAP_SETTINGS_STORAGE",
                      "CONFIG_ZMK_KEYMAP_LAYER_REORDERING"]}
PRELUDE = f"""#include <stdint.h>
#include <zephyr/sys/util_macro.h>
#define ZMK_KEYMAP_LEN 1
#define CONFIG_ZMK_KEYMAP_LAYER_NAME_MAX_LEN 20
struct zmk_behavior_binding {{ const char *behavior_dev; }};
{dt_mock()}
"""
print("layers from", keymap, "->", layers)
for v in variants:
    name, paths = v.split("=", 1)
    h, c = paths.split(":")
    code = extract(h, c)
    for cfg, defs in CONFIGS.items():
        with tempfile.NamedTemporaryFile("w", suffix=".c", delete=False) as f:
            f.write(PRELUDE + code + "\nint n_layers = ZMK_KEYMAP_LAYERS_LEN;\n")
        args = [os.environ.get("CC", "cc"), "-std=gnu11", "-I", inc] + \
               os.environ.get("PROBE_CFLAGS", "-Werror=excess-initializers").split() + \
               [f"-D{d}=1" for d in defs]
        r = subprocess.run(args + ["-fsyntax-only", f.name], capture_output=True, text=True)
        e = subprocess.run(args + ["-E", "-P", f.name], capture_output=True, text=True).stdout
        km = re.search(r"struct zmk_behavior_binding zmk_keymap\[.*?\]\[.*?\] = \{(.*?)\};", e, re.S)
        st = re.search(r"zmk_stock_keymap\[.*?\]\[.*?\] = \{(.*?)\};", e, re.S)
        stock = "n/a" if not st else ("ZEROED" if st.group(1).strip() == "0" else "populated")
        n = eval(re.search(r"int n_layers = (.*?);", e).group(1))
        errs = sorted({l.split("error: ")[1] for l in r.stderr.splitlines() if "error: " in l})
        print(f"{name:18} {cfg:9} LAYERS_LEN={n} "
              f"keymap={'ZEROED' if km.group(1).strip() == '0' else 'populated':9} stock={stock:9} "
              f"-> {'COMPILES' if r.returncode == 0 else 'FAILS: ' + '; '.join(errs)[:120]}")
        os.unlink(f.name)
```
