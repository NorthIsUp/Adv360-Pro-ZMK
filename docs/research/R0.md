# R0 — Docker build/test recipe for the Adv360 Pro on ZMK main

Scope: zmk `main` @ `9ebbeff0` (Zephyr `v4.1.0+zmk-fixes`, SDK 0.16.9), unmodified, on this Mac
(arm64 host, Docker Desktop, 16 CPUs visible in the container). Consumer: S0 (K6 harness), then every
section. All numbers below were measured on 2026-09-27 against the real repo and the real user config.

## Bottom line

1. **Image: `docker.io/zmkfirmware/zmk-build-arm:4.1`.** It is what main's CI uses (`build.yml`,
   `test.yml`, `ble-test.yml`); `.devcontainer/Dockerfile` uses `zmk-dev-arm:4.1-branch` (dev image, not
   needed). Local digest `sha256:edb1c953…`, **arm64 native**, so no emulation. `build-user-config.yml`
   still says `zmk-build-arm:stable`; do not use that for main.
2. **Board strings:** `adv360pro_left/nrf52840/zmk`, `adv360pro_right/nrf52840/zmk` (as R4). They build
   from `app/boards/kinesis/adv360pro/`.
3. **The volume `zmk-adv360-west` is complete.** Layout is a west topdir: `.west/config`
   (`manifest.path = zmk/app`), `zephyr/`, `modules/`, `tools/`, `optional/`, and an empty `zmk/` that the
   worktree is bind-mounted over. All 56 projects report `cloned`. `west update` is a no-op in 1.3 s:
   55 × "HEAD is now at", one shallow fetch of the `zephyr` branch `v4.1.0+zmk-fixes` (no new objects),
   nothing else. `.adv360-west.sha` in the volume equals `sha256(app/west.yml)` on main (`eb04caf…`).
4. **Parallelism flag:** `west build … -- -j6` is **wrong** (`--` goes to CMake: `CMake Error: Unknown
   argument -j6`). Use `west build -o=-j6` or env `CMAKE_BUILD_PARALLEL_LEVEL=6` (the harness sets the
   env; `ps` in the container shows `/usr/bin/ninja -j 6`).
5. **Worktrees need their gitdir mounted.** A worktree's `.git` is a file pointing at
   `/Users/adam/src/zmk-adv360/.git/worktrees/<name>`; without that path in the container, git fails
   (`fatal: not a git repository`). Mount the common gitdir at the same absolute path, read-only.
6. **The user keymap as it sits today does not reach the build.** With `-DZMK_CONFIG=<copy of config>`
   alone the build *succeeds* using the board's stock `adv360pro.keymap`: ZMK's lookup
   (`app/boards/post_boards_shields.cmake:84`) tries `adv360pro_left_nrf52840_zmk`, `adv360pro_left`,
   `adv360pro`, never `adv360`. The harness must pass `-DKEYMAP_FILE=…/adv360.keymap` (or S6 renames the
   file). With that, the **only** port-caused failure is `&stp` (`dt-bindings/zmk/stp.h` missing).
7. Tests run on arm64 inside the container: `toggle-layer` 4/4 PASS in 23 s, `backlight` 6/6 PASS in
   43 s; a corrupted snapshot makes the harness print `FAIL` and exit 1 (negative control).

## Measured build times

ccache (`/usr/bin/ccache`, `CCACHE_DIR=/root/.cache/ccache`, container-local, so it is lost when the
container is recreated) is on by default.

### adv360-env.sh

```bash
#!/usr/bin/env bash
# Copyright (c) 2026 The ZMK Contributors
# SPDX-License-Identifier: MIT
#
# adv360-env.sh up|exec <cmd...>|down|name
# One long-lived container per worktree; west workspace (zephyr + modules) in a
# shared named volume mounted at /workspaces, worktree bind-mounted over
# /workspaces/zmk so `west init -l zmk/app` resolves the same for every worktree.
set -euo pipefail

IMAGE=${ADV360_IMAGE:-docker.io/zmkfirmware/zmk-build-arm:4.1}
VOLUME=${ADV360_VOLUME:-zmk-adv360-west}
JOBS=${ADV360_JOBS:-6}
WT=$(git -C "$(dirname "$0")" rev-parse --show-toplevel)
NAME=zmk-adv360-$(basename "$WT")
# A worktree's .git file points at the main repo's absolute gitdir; mount it at
# the same path so git (and Zephyr's version stamp) works inside the container.
GITDIR=$(git -C "$WT" rev-parse --path-format=absolute --git-common-dir)

running() { [ "$(docker inspect -f '{{.State.Running}}' "$NAME" 2>/dev/null)" = true ]; }

up() {
    if ! running; then
        docker rm -f "$NAME" >/dev/null 2>&1 || true
        docker run -d --name "$NAME" \
            -v "$VOLUME":/workspaces \
            -v "$WT":/workspaces/zmk \
            -v "$GITDIR":"$GITDIR":ro \
            -e CMAKE_BUILD_PARALLEL_LEVEL="$JOBS" \
            -w /workspaces/zmk "$IMAGE" sleep infinity >/dev/null
    fi
    # Workspace init/update is shared by every container: serialize it, and only
    # re-run `west update` when app/west.yml changes.
    docker exec -w /workspaces "$NAME" bash -ec '
        git config --global --add safe.directory "*"
        exec 9>/workspaces/.adv360.lock; flock 9
        # `west init -l zmk/app` would make zmk/ the topdir (inside the bind
        # mount); pin the topdir to the volume instead.
        [ -f .west/config ] || { mkdir -p .west; printf "[manifest]\npath = zmk/app\nfile = west.yml\n\n[zephyr]\nbase = zephyr\n" >.west/config; }
        want=$(sha256sum zmk/app/west.yml | cut -d" " -f1)
        if [ "$(cat .adv360-west.sha 2>/dev/null)" != "$want" ]; then
            west update --fetch-opt=--filter=tree:0 && echo "$want" >.adv360-west.sha
        fi
        west zephyr-export >/dev/null'
    echo "$NAME"
}

case "${1:-}" in
up) up ;;
exec) shift; running || up >/dev/null; docker exec -w /workspaces/zmk "$NAME" "$@" ;;
down) docker rm -f "$NAME" >/dev/null ;;
name) echo "$NAME" ;;
*) echo "usage: $0 up|exec <cmd...>|down|name" >&2; exit 2 ;;
esac
```

### adv360-build.sh

```bash
#!/usr/bin/env bash
# Copyright (c) 2026 The ZMK Contributors
# SPDX-License-Identifier: MIT
#
# adv360-build.sh <left|right> [--studio] [--pristine] [--config <dir> [--keymap <file>]]
#   --config: ZMK_CONFIG dir relative to the worktree root (must be inside it, e.g.
#             zmk-config/, which .gitignore covers); builds into build/<side>[-studio]-config.
#   --keymap: KEYMAP_FILE relative to the worktree root. Needed when the config's keymap
#             is not named adv360pro*.keymap: otherwise the board's stock keymap is used
#             silently.
# Prints "UF2: build/<side>[-studio][-config]/zephyr/zmk.uf2" on success.
set -euo pipefail
HERE=$(cd "$(dirname "$0")" && pwd)

side=${1:-}
case "$side" in left | right) shift ;; *) echo "usage: $0 <left|right> [--studio] [--pristine] [--config <dir> [--keymap <file>]]" >&2; exit 2 ;; esac
studio='' pristine='' config='' keymap=''
while [ $# -gt 0 ]; do
    case "$1" in
    --studio) studio=1 ;;
    --pristine) pristine=1 ;;
    --config) config=$2; shift ;;
    --keymap) keymap=$2; shift ;;
    *) echo "unknown arg: $1" >&2; exit 2 ;;
    esac
    shift
done

dir=build/$side${studio:+-studio}${config:+-config}
# Bare adv360pro_<side> resolves to a stub target and fails (R4); keep the full HWMv2 string.
args=(west build -s app -d "$dir" -b "adv360pro_${side}/nrf52840/zmk")
[ -n "$pristine" ] && args+=(-p)
[ -n "$studio" ] && args+=(-S studio-rpc-usb-uart)
args+=(--)
[ -n "$studio" ] && args+=(-DCONFIG_ZMK_STUDIO=y)
[ -n "$config" ] && args+=("-DZMK_CONFIG=/workspaces/zmk/$config")
[ -n "$keymap" ] && args+=("-DKEYMAP_FILE=/workspaces/zmk/$keymap")

"$HERE/adv360-env.sh" exec "${args[@]}"
echo "UF2: $dir/zephyr/zmk.uf2"
```

### adv360-test.sh

```bash
#!/usr/bin/env bash
# Copyright (c) 2026 The ZMK Contributors
# SPDX-License-Identifier: MIT
#
# adv360-test.sh [<app/tests/path> ...]   (paths relative to the worktree root)
# Runs app/run-test.sh per path inside the container (native_sim is Linux-only).
set -uo pipefail
HERE=$(cd "$(dirname "$0")" && pwd)

# ponytail: default set is the suites touching Kinesis features on main today;
# sections append their new suites here.
[ $# -gt 0 ] || set -- app/tests/backlight app/tests/toggle-layer app/tests/momentary-layer app/tests/studio

fail=0
for p in "$@"; do
    if "$HERE/adv360-env.sh" exec env ZMK_BUILD_DIR=/workspaces/zmk/build J="${ADV360_JOBS:-6}" \
        sh -c "cd app && ./run-test.sh '${p#app/}'">&2; then
        echo "PASS $p"
    else
        echo "FAIL $p"
        fail=1
    fi
done
exit $fail
```

## Rules for later agents

- One container per worktree, named `zmk-adv360-<worktree-basename>`; only `down` your own. Live
  containers seen during this run: `zmk-adv360-r1`, `zmk-adv360-r1-x86` (not mine, left alone).
- Never write to the volume except `build/<label>/` scratch and the harness's lock/sha files; never
  `west update` by hand when the sha matches.
- Run the harness from the host inside the worktree (`app/boards/kinesis/adv360pro/tools/…`); scripts
  are bash, so call them directly, not through zsh word-splitting tricks (`$a` holding "left --studio"
  does not split in zsh).
- `ZMK_BUILD_DIR=/workspaces/zmk/build` puts test builds in `<worktree>/build/tests/`, ignored by
  `.gitignore` (`/build`).
- ccache is container-local: the first pristine build after `down`/`up` runs uncached (left: 17 s in the
  volume, versus 13–14 s for later pristine builds with a warm cache).
