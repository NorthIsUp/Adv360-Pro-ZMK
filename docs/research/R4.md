# R4 — Zephyr 3.5 → 4.1 API drift in the Kinesis lighting, backlight and split code

Scope: the Kinesis versions of `app/src/rgb_underglow.c`, `backlight.c`, `ext_power_generic.c`,
`behaviors/behavior_{rgb_underglow,backlight,stp_indicators,mouse_key_press}.c` and
`split/bluetooth/{central,service}.c` (`kinesis/adv360-z3.5-2`), compared with zmk `main` @ `9ebbeff0`
(Zephyr `v4.1.0+zmk-fixes`, SDK 0.16.9 arm-zephyr-eabi-gcc). Consumers: S1 (backlight), S2 (lighting),
S3 (split sync), S4 (behaviors).

## Bottom line

1. **Zephyr drift for these files is nil.** Every Zephyr API the Kinesis hunks call (LED strip, settings,
   `k_work`/`k_work_delayable`, `K_THREAD_STACK_DEFINE`, `K_MSGQ_DEFINE`, `k_timer`, device/DT macros,
   GATT write/attr APIs, `SYS_INIT`) has the same signature on 4.1. A compiled probe (below) asserts each
   signature with `__builtin_types_compatible_p` inside a real `adv360pro_*` build, and a negative
   control proves the asserts fire.
2. **ZMK drift is only in split.** `app/include/zmk/split/bluetooth/central.h` was deleted upstream
   (#2766, full-duplex wired split). Central-side Kinesis code includes it and calls
   `zmk_split_bt_update_led()`/`zmk_split_bt_update_bl()`. That is the only compile break in the
   lighting/backlight files. S3's K1 helpers (`zmk_split_central_update_kinesis_{led,backlight}`) replace it.
3. **`rgb_underglow.c`, `backlight.c`, `ext_power_generic.c`, `rgb_underglow.h`, `backlight.h`, `rgb.h`
   are byte-identical on main and the merge-base 3377ed02.** No upstream refactor since 2025-01 touched
   them (`git diff --shortstat 3377ed02 9ebbeff0 -- <those files>` prints nothing). All 15
   `rgb_underglow.c` hunks apply with `git apply` at their original line numbers.
4. With a 6-line shim for the deleted header plus `CONFIG_ZMK_HID_INDICATORS=y`, the whole Kinesis
   lighting/backlight/behavior set **compiles and links on both halves, no-clique and clique**.
5. `CONFIG_ZMK_HID_INDICATORS` is **not** in main's adv360pro defconfigs (the Kinesis left defconfig
   had it). Without it the left half fails to link: `undefined reference to
   zmk_hid_indicators_get_current_profile`. S0/S2 must add it (left), and
   `CONFIG_ZMK_SPLIT_PERIPHERAL_HID_INDICATORS=y` on both halves for C2 on the right.

### S3 note: central-side connect event

The Kinesis re-sync (rgb + backlight `k_work_reschedule(…, K_MSEC(2500))` on connect) listens for
`zmk_split_peripheral_status_changed` on the **central**. Main raises that event only on the
peripheral. Two options:

- raise it from `split/bluetooth/central.c` `split_central_connected`/`_disconnected`, as Kinesis did
  (BLE-only);
- raise it from the transport-agnostic `split/central.c` `transport_status_changed_cb`, which BLE central
  already calls on connect/disconnect through `notify_status_work` (central.c:948,981).

The second fits K1's transport-agnostic rule. S3 owns the choice.

## Non-API defects in the Kinesis hunks (found while mapping; fix while porting)

- `rgb_underglow.c` hunk 14: the USB branch calls `zmk_split_bt_update_led` with no central guard and
  declares an unused `static bool prev_state`.
- `rgb_underglow.c` hunks 4 and 9: `last_ble_state` and `ext_power` are declared under Kconfig guards,
  but code that is not guarded uses them.
- `service.c` write handlers use `memcpy(payload + offset, …)` on a struct pointer (scaled offset).
- Central send code writes to `peripherals[0]` only. Main's run-queue path addresses
  `peripherals[wrapper.source]`, and K1 says "broadcast to every connected peripheral source".
- `behavior_stp_indicators.c`: its metadata tables sit outside the `CONFIG_ZMK_BEHAVIOR_METADATA` guard
  (unused-variable warning), and it keeps a no-op init that upstream style drops.
